# RoomGuestBook

GitHub Pages 정적 페이지 + Google Apps Script + 구글 시트. 서버 없음.
목적은 출석 증명이 아니라 **출입 문서화**입니다.

## 어떻게 동작하나

```
접속 → 구글 계정 자동 확인(One Tap)
   ↓
members 탭에 내 이메일이 있나?
   ├─ 없다 → 이름·학번(12자리) 입력 → members에 자동 추가 → 기록
   └─ 있다 → 「홍길동님으로 방명록 남기기」 버튼 한 번 → 기록
   ↓
동아리방 반경 밖이라면 → 기록하지 않고 "근처에서만 가능"
1시간 안에 이미 남겼다면 → 기록하지 않고 "이미 기록됨"
   ↓
최근 1시간 입장자를 홍*동 형태로 3명 + "외 n명" 표시
```

**자가 등록 방식입니다.** `members` 탭은 처음엔 헤더만 있는 빈 탭이고, 첫 방문자가
스스로 이름·학번을 채웁니다. 운영진이 명단을 미리 준비할 필요가 없습니다.
두 번째 방문부터는 다시 묻지 않고 버튼 한 번으로 끝납니다.

### 이름은 계정당 한 번, 그 뒤로는 고정입니다

이름·학번을 적는 화면은 `members` 탭에 그 이메일이 없을 때만 나옵니다.
한 번 등록된 뒤에는 브라우저가 무엇을 보내든 **서버가 쳐다보지도 않고**,
방명록에는 항상 시트에 적힌 값이 들어갑니다. 본인은 바꿀 방법이 없습니다.

등록과 기록은 `LockService`로 직렬화되므로, 버튼을 연타하거나 두 기기에서
동시에 눌러도 이름이 두 벌 생기지 않습니다.

**고치거나 지우는 일은 오직 임원진이 `members` 탭을 직접 편집해야 합니다.**

| 하고 싶은 일 | 방법 |
|---|---|
| 오타 난 이름·학번 수정 | `members` 탭에서 해당 칸을 직접 고침 → 다음 기록부터 반영 |
| 탈퇴·제명 | `members` 탭에서 해당 행 삭제 → 다음 접속 때 등록 화면부터 다시 |
| 지난 방명록 기록 정정 | `방명록` 탭에서 직접 수정 (기록은 로그라 자동으로 바뀌지 않음) |

학번 칸을 고칠 때는 앞자리 `0`이 잘리지 않도록 **텍스트 서식**을 유지하세요.

**다른 곳에서 남기는 것을 막기 위해 위치를 확인합니다.** 반경 안이면 기록되고,
밖이면 거부됩니다. `config` 탭의 `lat`/`lon`을 비워두면 검사 없이 좌표만 기록합니다.

## 공개되는 것과 그렇지 않은 것

GitHub에는 **`index.html`만** 올립니다. `Code.gs`는 시트에 붙어 실행되는 서버 코드라
저장소에 올릴 필요가 없고, `.gitignore`로 제외해 두었습니다.

| | 위치 | 공개 여부 |
|---|---|---|
| 동아리방 좌표·허용 반경 | 시트 `config` 탭 | **비공개** |
| 이메일·학번·기록된 좌표 | 시트 `members` / `방명록` 탭 | **비공개** |
| 서버 코드 (`Code.gs`) | 시트의 Apps Script | **비공개** |
| OAuth 클라이언트 ID, 웹앱 URL | `index.html` | 공개 (공개 전제 값) |

### 응답 규칙 (코드로 강제)

값은 브라우저 → 서버 **한 방향으로만** 갑니다. 서버가 돌려주는 것은
**참/거짓과 마스킹된 이름뿐**이며, `Code.gs`의 화이트리스트로 강제됩니다.

```js
const REPLY_KEYS = ['ok', 'recent', 'needProfile', 'visitors', 'more'];
```

모든 응답이 `reply_()`를 거치므로 목록에 없는 키는 실수로 넣어도 걸러집니다.
좌표는 물론 **이메일·학번·본인 실명도 목록에 없어 나갈 수 없습니다.**
로그인한 본인 이름은 서버가 아니라 브라우저가 가진 구글 토큰에서 읽습니다.

**실패 이유도 알려주지 않습니다.** "이미 등록된 학번"이라고 답하면 학번을 하나씩
넣어보며 누가 가입했는지 알아낼 수 있고, "반경 밖"이라고 답하면 좌표를 좁힐 수 있습니다.
거부는 `{ ok: false }` 하나로만 돌아가고, 이유는 **Apps Script 실행 로그**에만 남습니다.
운영진은 편집기의 **실행 기록**에서 `거부: 학번-중복` 같은 줄을 확인할 수 있습니다.

`REPLY_KEYS`에 키를 추가할 때는 그 값이 유출돼도 되는지 반드시 따져보세요.
`test_()`가 이 필터를 검사합니다.

### 막아둔 것

| 공격 | 방어 |
|---|---|
| 토큰 위조 | 구글 `tokeninfo`로 검증 + `aud`가 우리 클라이언트 ID인지 확인 |
| 남의 사이트에서 로그인 | 승인된 JavaScript 원본 제한 (설정 3번) |
| 응답으로 정보 캐가기 | `REPLY_KEYS` 화이트리스트 — 참/거짓과 마스킹 이름만 |
| 이름에 `=IMPORTXML(...)` 넣어 시트에서 실행 | `safe_()`가 텍스트로 못박음, 40자 제한 |
| 남의 학번으로 두 번째 계정 만들기 | 이미 등록된 학번이면 거부 |
| 등록 후 이름 바꿔치기 | 등록된 계정은 요청의 이름·학번을 무시하고 시트 값만 사용 |
| 연타·동시 요청으로 중복 등록 | `LockService`로 등록·기록 구간 직렬화 |
| 반경 밖에서 명단만 등록해두기 | 위치 검사를 등록보다 먼저 수행 |
| 좌표 설정을 깜빡해 검사가 꺼진 줄 모름 | 일부만 채워지면 통과 대신 거부 (fail-closed) |
| 학번을 넣어보며 가입자 열거 | 실패 이유를 알려주지 않음 — `{ ok: false }` 하나뿐 |
| 반경 안/밖 응답으로 좌표 역산 | 같은 이유로 반경 밖도 일반 거부와 구분되지 않음 |
| 페이지 XSS | 사용자 문자열은 전부 `textContent`로 삽입 |
| 웹앱 URL을 브라우저로 열기 | `doGet` 없음 — 아무것도 나오지 않음 |

### 남는 한계 (출입 문서화 용도에서는 대체로 무해)

1. **본인이 자기 기록을 위조할 수 있습니다.** 브라우저 개발자도구에서 로그인 토큰을
   꺼내 직접 요청하면 페이지를 열지 않고도 기록이 남고, 좌표도 임의 값으로 보낼 수 있습니다.
   다만 토큰은 본인 것이라 **남을 사칭하지는 못합니다.**
2. **학번 선점.** 아직 등록하지 않은 사람의 학번을 먼저 적어 등록할 수 있습니다.
   자가 등록 방식의 대가입니다. `members` 탭을 가끔 훑어보세요.
3. **할당량.** 웹앱 URL은 페이지에 노출됩니다. 대량 요청으로 Apps Script
   일일 한도를 태우면 하루 동안 기록이 멈출 수 있습니다.
4. **마스킹의 한계.** 인원이 적으면 `홍*동`으로도 누군지 짐작됩니다.

## 설정 (한 번만)

### 1. 시트 탭 만들기

시트 → **확장 프로그램 → Apps Script** → `Code.gs` 붙여넣기 →
함수 목록에서 **`setup`** 선택 후 실행. 탭 세 개가 헤더까지 자동으로 생깁니다.

| 탭 이름 | 1행 헤더 |
|---|---|
| `members` | 이메일 / 이름 / 학번 / 최초등록 |
| `방명록` | 시각 / 이름 / 학번 / 이메일 / 위도 / 경도 / 정확도(m) |
| `config` | (헤더 없음) A열 이름 / B열 값 |

`setup`이 만들어 둔 `config` 탭의 B열 두 칸을 채웁니다. **직접 입력하세요.**

| A | B |
|---|---|
| `lat` | (비어 있음 → 위도 입력) |
| `lon` | (비어 있음 → 경도 입력) |
| `radius_m` | `150` (실측하며 조정) |

좌표는 구글 지도에서 해당 건물을 **우클릭 → 맨 위 좌표 클릭**하면 복사됩니다.
실내 GPS는 오차가 크므로 처음엔 150~200m로 넉넉히 잡고, 동아리방과 캠퍼스 밖에서
각각 눌러보며 줄여가세요. `lat`/`lon`을 비워두면 검사 없이 좌표만 기록합니다.

### 2. Apps Script 배포

1. **배포 → 새 배포 → 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
2. 발급된 웹 앱 URL 복사 (`https://script.google.com/macros/s/.../exec`)

> 코드를 고친 뒤에는 **배포 관리 → 편집 → 새 버전**으로 다시 배포해야 반영됩니다.

#### "Google hasn't verified this app" 경고

`setup` 실행이나 배포 승인 단계에서 뜹니다. **정상이며, 본인만 보는 화면입니다.**

> 고급(Advanced) → *(안전하지 않음)으로 이동* → 허용

내가 만든 스크립트에 내 시트 접근 권한을 주는 절차라서 그렇습니다. 검증 심사는
앱을 남의 계정 데이터에 접근시킬 때 필요한 것이고, 여기서는 스크립트가 **내 시트에만**
접근합니다. 웹 앱을 "실행 계정: 나"로 배포하므로 **동아리원은 이 화면을 보지 않습니다.**

동아리원이 보는 로그인은 이름·이메일만 받는 기본 스코프(`openid` / `email` / `profile`)라
검증 대상이 아닙니다. 3번에서 민감한 스코프를 추가하지 마세요.

### 3. OAuth 클라이언트 ID

1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → 사용자 인증 정보 만들기 → **OAuth 클라이언트 ID** → 웹 애플리케이션
2. **승인된 JavaScript 원본**에 `https://mana-kus.github.io` 추가
   (로컬 테스트하려면 `http://localhost:8000`도 함께)
3. OAuth 동의 화면은 **외부 / 게시됨** 상태여야 동아리원 전체가 로그인할 수 있습니다.
   테스트 모드로 두면 등록한 테스트 사용자만 됩니다.

### 4. 값 채우기

- `index.html` 상단의 `CLIENT_ID`, `ENDPOINT`
- `Code.gs` 상단의 `CLIENT_ID` (같은 값)

### 5. GitHub Pages 켜기

저장소 **Settings → Pages → Source: `main` / `(root)`** → Save.
1~2분 뒤 `https://mana-kus.github.io/RoomGuestBook/` 에서 열립니다.

동아리원에게 보낼 링크는 이 주소입니다. **시트 링크는 절대 공유하지 마세요.**

값을 채운 뒤 반영하려면:

```
git add index.html && git commit -m "설정값 반영" && git push
```

## Code.gs 는 이 저장소에 없습니다

서버 코드는 공개 저장소에 두지 않습니다. 원본은 로컬에만 있고,
실제로 실행되는 사본은 시트의 Apps Script 편집기 안에 있습니다.

```
C:\Users\lovel\Desktop\방명록\Code.gs
```

`.gitignore`가 `Code.gs`를 제외하므로 실수로 커밋되지 않습니다.
`git status`에 `Code.gs`가 보이면 커밋하지 마세요.

명단 집계, 응답 화이트리스트를 검사합니다.
통과하면 로그에 `ok`, 실패하면 예외가 납니다.
